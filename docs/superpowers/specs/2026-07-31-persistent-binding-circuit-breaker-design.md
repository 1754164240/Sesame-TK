# 持久调度绑定熔断设计

## 目标

当支付宝进程无法绑定模块的持久调度服务时，只执行一轮受控重试，随后在当前进程内熔断并立即回退进程内调度，避免重复绑定占用启动线程。

## 设计

- 熔断状态由 `PersistentSchedulerRuntime` 持有，在同一支付宝进程内的网关实例之间共享。
- 同一时间只允许一个调用执行绑定；其他入口直接收到持久服务不可用结果。
- 两次绑定均失败后保持熔断，支付宝进程重启后通过进程内静态状态重建自动恢复尝试。
- 轮询、定时唤醒和验证探针捕获持久服务不可用结果并立即执行已有的进程内调度。
- 持久调度的绑定及协调工作运行在 I/O 调度器，不占用主任务的计算调度器。

## 验证

- 单元测试验证单绑定在途、失败后熔断和成功后释放。
- 单元测试验证持久服务不可用时轮询、唤醒和验证探针均执行进程内回退。
- 执行相关单元测试、Debug 构建、UTF-8 无 BOM 和 `git diff --check`。
