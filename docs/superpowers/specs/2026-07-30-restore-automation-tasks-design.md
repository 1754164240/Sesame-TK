# 7 月 29 日自动任务恢复设计

## 目标

恢复 7 月 29 日安全闭环中被降级的四类自动任务：

1. 庄园小游戏成绩提交与奖励处理。
2. 新村 XLight 广告任务。
3. 文体中心普通日常任务。
4. 游戏中心真实游戏、广告、报名、完成与领奖任务。

所有动作必须以服务端状态回查作为完成依据。购买、充值、提现、兑换、借贷、投资、现金和捐赠类任务继续阻断。

## 总体原则

- 任务参数优先来自当前列表、详情或广告查询响应。
- 不复用旧账号、会话、播放业务 ID 或事件对象。
- RPC 返回成功不等于任务完成，必须回查对应任务列表。
- 回查状态没有推进时停止当前任务，不继续叠加请求。
- 每个工作流设置有限步骤和有限重复次数。
- 单项失败只中止当前任务，不阻断后续安全任务。
- 缺少任务 ID、业务类型、游戏入口、广告事件或其他必要字段时跳过。

## 庄园小游戏

恢复 `recordFarmGame` 成绩提交，并保留四类游戏原有分数范围。流程为：

1. 调用 `initFarmGame` 读取剩余次数和三级奖励状态。
2. 剩余次数大于零时生成本次 UUID、摘要和游戏分数。
3. 调用 `recordFarmGame`。
4. 等待短暂同步后再次调用 `initFarmGame`。
5. 仅当剩余次数减少或三级奖励状态推进时确认本轮成功。
6. 状态无进展、结构未知或请求失败时停止当前游戏。

飞行赛和揍小鸡的额外次数任务沿用任务列表、完成、领奖链路，并在每次动作后重新查询。

## 新村 XLight

恢复 XLight 查询和广告事件完成接口。流程为：

1. 从新村任务列表识别 `ANTSTALL_XLIGHT_VARIABLE_AWARD`。
2. 调用 `xlightPlugin` 获取实时 `playingBizId` 和事件列表。
3. 对每个完整事件调用 `interaction.finish`。
4. 等待服务端要求时长；缺少时长时使用受限默认值。
5. 重新查询新村任务列表。
6. 仅在任务状态推进后领取奖励。

命中 XLight 流量限制码时结束本轮，不重复请求。广告查询缺少播放 ID 或事件对象时跳过。

## 文体中心普通任务

扩展现有 `SportsTaskWorkflow`，允许 `SPORTS_DAILY_GROUP` 中不包含风险信号的普通 `TODO` 任务：

1. 解析 `taskId`、`bizType`、`status` 和 `userTaskId`。
2. 广告、游戏、资金和未知语义任务继续跳过。
3. 对普通任务调用 `userTaskComplete(bizType, taskId)`。
4. 重新查询同一任务组。
5. 仅在状态从 `TODO` 推进到可领奖或终态时确认。
6. 对可领奖任务调用 `userTaskRightsReceive` 并再次回查。

任务组结构未知、业务类型为空或回查无进展时保留后续重试。

## 游戏中心

游戏中心同时处理 v4 平台任务和 P2E 任务，恢复以下动作：

- 报名：使用 `doTaskSignup` 或 `platformTaskSignUp`。
- 启动游戏：使用任务响应中的 `jumpLink` 启动支付宝深链。
- 模拟游戏过程：只使用任务响应中的游戏 ID、应用 ID、次数、时长和扩展参数。
- 发送或完成：使用 `doTaskSend` 或 `platformTaskComplete`。
- 广告事件：先查询实时广告播放信息，再使用当次响应中的 `playingBizId` 和 `playEventInfo` 完成事件。
- 领奖：使用现有领奖 RPC。

真实游戏和广告工作流按以下顺序执行：

1. 查询任务并建立动作前快照。
2. 必要时报名，并回查报名状态。
3. 校验并启动任务提供的支付宝深链。
4. 按任务要求等待或执行有限次数的游戏进度请求。
5. 广告任务查询实时播放信息并逐个提交事件。
6. 调用任务完成 RPC。
7. 重新查询同一任务，确认状态推进。
8. 进入可领奖状态后领取，并再次回查终态。

禁止根据标题猜测游戏 ID、入口或广告事件。深链只允许支付宝 `alipays`/`alipay` 协议及服务端明确提供的 HTTPS 地址。

## 错误处理与熔断

- 每个任务最多处理一次完整动作链；只有回查确认推进后才允许进入下一阶段。
- 同一列表中按稳定任务 ID 去重。
- 单个工作流设置总步骤上限，达到上限后停止。
- 空响应、解析失败、验证拦截、离线和未知结果不写完成标记。
- Android 页面启动失败时记录并跳过，不把 RPC 成功当作替代证据。
