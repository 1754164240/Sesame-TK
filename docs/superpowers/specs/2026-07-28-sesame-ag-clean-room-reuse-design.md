# Sesame-AG Clean-room 复用设计

## 目标

在不复制、移植或 cherry-pick Sesame-AG AGPL 源码的前提下，将已审计且适合当前项目的功能设计全部独立实现到 Sesame-VN。实现必须服从当前项目的 libxposed API 102、现有模型体系、RPC Bridge、配置存储和协程调度架构。

## 全局约束

- 仅支持 libxposed API 102，不恢复 API 82、100 或旧 Xposed 入口。
- Sesame-AG 仅作为行为和协议研究资料，不复制其源码、注释或结构。
- 不引入 Sesame-AG 的通用 `TaskFlow`；各业务使用小型策略类和工作流类增量适配。
- 新增功能和新增动作开关默认关闭。
- 只有 RPC 回查确认终态后才能写入“完成”“已领取”或每日状态标记。
- 对未知响应、空响应、结构变化和未确认状态保留重试，不伪造成功。
- 不实现提现、借贷、充值、下单、付费兑换、广告伪完成、真实游戏任务或游戏改分。
- 金融相关模块只允许查询、签到和服务端明确免费的奖励领取。
- 所有文件使用 UTF-8 无 BOM；新增代码注释使用中文。
- 不在本实施过程中自动创建 Git 提交。

## 交付域一：近期提交验收

### API 102

保留 `modern.HookEntry`、`ModernXposedRuntime` 和当前反射帮助器。通过单元测试验证旧入口和旧 API 依赖不存在，并通过真机验证 Hook 注入、RPC 调用、模块重载和目标应用重启。

### 福气鱼池

保留当前 `FishPondPolicy` 与 `FishPondWorkflow` 分层。补充每日单次运行映射和真实响应兼容测试。兑换必须在首页或同步结果显示可兑换时执行，兑换后重新查询首页。广告 `adBizNo` 和额外广告鱼竿不执行。

### 森林 1V1、会员宝箱与新版任务协议

为当前实现补充取消、重载、重复运行、响应结构变化和动作后状态未刷新场景。任何本地“动作成功”都不能代替服务端终态。

## 交付域二：基础协议与运行状态

### ReferToken

统一接受 `requestData` 为 `JSONArray`、`JSONObject`、JSON 字符串数组、JSON 字符串对象或根对象。非法字符串和空 Token 返回 `null`，不抛出异常。

### relationLocal

保留 `RequestManager -> RpcBridge -> RpcEntity` 现有链路。增加契约测试，确保新旧 Bridge 都不会把 relation 参数误放到 `appName`，并保留结构化空响应。

### 日志

增加跨天检测器。每次文件日志写入前低成本检查日期边界，跨天时原子重建文件 Appender。多进程竞争时允许重复检测，但不能继续写入前一天文件或破坏现有日志。

### 通知

常驻状态、异常消息和一次性业务消息使用独立 Builder、通知 ID 和更新状态。异常通知不得修改常驻通知的标题、正文、节流时间或 Manager 引用。

### 并发

主任务并发和森林好友并发分别配置。默认值保持 3 和 60，并提供安全上下限。一次执行使用启动时快照，运行中修改配置只影响下一轮。

## 交付域三：现有业务闭环升级

### 森林

完善抽抽乐的查询、动作、重新查询闭环；删除没有服务端证据的累计奖励推定。增加总浇水开关、随机浇水通知、收能量前优先浇水、保护罩续用阈值，均默认关闭。

### 青春特权

将森林内旧实现整理为独立模块，提供签到、森林道具和青春任务三个开关。首批只启用签到与免费道具协议；青春任务保持默认关闭，并使用白名单识别。

### 运动

兼容健康岛多种任务容器、任务 ID、泡泡和奖励记录结构。实现查询、签到、运动问答、城市见闻及免费奖励回查。动态价格赎回自己只提供状态查询，不执行购买。

### 庄园、果园和芝麻信用

完善延迟奖励凭据、领奖容量、失败分类及重新查询。庄园捐蛋排位和装扮商城只实现查询与免费领奖，不自动捐蛋或兑换。芝麻炼金不实现满级红包提现。

### 海洋与网商银行

海洋摸鱼仅实现活动查询、签到和免费奖励，不执行真实游戏。网商银行作为独立高风险模块，首版只开放查询、签到和明确免费奖励，并默认关闭。

## 交付域四：会员安全任务

会员任务解析兼容数组、根对象和嵌套容器。`CALL_APP`、浏览访问和领奖动作后必须重新查询。

允许实现：

- 会员签到、宝箱和限时免费访问奖励；
- 账单贴纸与拼贴世界的查询、签到和免费领奖；
- 游戏中心状态查询、签到、免费宝箱、免费金币和已完成任务领奖；
- P2E 平台的查询、签到、免费浏览奖励和免费抽金币。

禁止实现：

- 赚现金提现；
- 充值、借贷、下单或付费兑换；
- 真实游戏、广告伪完成和游戏改分；
- 任何无法通过回查确认的奖励动作。

## 交付域五：配置迁移

在现有导入导出入口上增加版本化包格式，区分通用配置、账号私有配置和可选缓存。导入流程必须预解析、校验版本、展示作用域和冲突，再由用户确认应用。兼容旧版配置文件，保留导入前历史快照并支持恢复。

## 交付域六：好友中心

建立好友仓库、关系快照、分组、全局黑名单和玩法能力记录。先提供只读好友中心、主动刷新和每日首次同步，再逐模块迁移好友选择字段。旧选择值必须可迁移且不能静默丢失。

## 交付域七：持久系统调度

在现有 `AlarmManager` 基础上增加计划注册表、稳定 `dedupeKey`、单一物理闹钟和到期批量路由。支持进程死亡、设备重启、应用升级、时区或系统时间变化后的恢复。

前台拉起目标应用使用独立总开关且默认关闭。首批接入全局定时执行和森林蹲点，稳定后接入庄园、运动和新村子任务。失败时回退进程内调度，不阻塞宿主主线程。

## 错误处理

- JSON 解析失败返回明确的未知或可重试状态，并保留脱敏原始响应摘要。
- RPC 空响应由 `RequestManager` 统一转为结构化失败，业务层不得直接解析空字符串。
- 风控、安全验证和频率限制停止当前动作，不自动扩大重试。
- 取消信号必须向子工作流传播；重载前等待旧任务退出。
- 每日状态只保存服务端确认结果，临时“已提交”使用独立待确认状态。

## 测试与验收

- 每个新策略、解析器和状态机先写失败单元测试，再写实现。
- 每个动作工作流覆盖成功、空响应、失败、状态未刷新、重复执行和取消。
- 配置迁移覆盖旧格式、跨账号、未知字段、冲突和历史恢复。
- 持久调度覆盖重复注册、取消、到期、重启恢复、时间变化和批量同窗任务。
- 每个交付域完成后运行定向测试；最终运行 `testDebugUnitTest` 和 Debug 构建。
- API 102、通知、AlarmManager、进程死亡恢复和真实 RPC 需要 Android 真机验收。

1. 近期提交验收与基础协议修复。

3. 森林、青春特权、运动、庄园、果园、芝麻信用闭环。
4. 会员安全任务、海洋与网商银行。
5. 配置迁移和好友中心。
6. 持久系统调度。
7. 全量回归、真机验收和完成度审计。
